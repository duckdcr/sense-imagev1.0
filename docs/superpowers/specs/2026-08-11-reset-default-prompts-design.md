# 恢复源码默认提示词功能设计

## 目标

为白底图和场景图分别提供安全的一键恢复入口。当用户误改内置提示词时，可恢复该功能对应的源码默认提示词，不影响另一类提示词，也不需要手动复制长文本。

## 界面行为

- 白底图页面在“修改提示词”按钮之后增加“恢复默认提示词”按钮。
- 场景图页面在“修改提示词”按钮之后增加“恢复默认提示词”按钮。
- 点击按钮后显示确认对话框，明确说明只恢复当前功能对应的提示词。
- 用户取消时不发送请求、不修改配置。
- 用户确认后按钮临时禁用，防止重复提交。
- 成功后显示“白底图提示词已恢复为源码默认值”或“场景图提示词已恢复为源码默认值”。
- 失败时保留现有自定义配置，并显示服务端返回的错误信息。

## 服务端与存储语义

- 新增 `DELETE /api/editable-prompt-templates/:kind`。
- `kind` 仅允许 `manual_product` 和 `curtain_creation`。
- 提示词存储层新增 `reset(kind)`，删除该类型的自定义覆盖值，并返回源码默认提示词。
- 重置一种提示词时，另一种提示词的自定义值必须保持不变。
- `config/prompts.json` 只承担自定义覆盖存储；被重置的类型不再写入该文件，后续读取时自动回退到源码常量。
- 生成任务始终通过现有服务端运行时适配器读取当前有效提示词，因此重置后的下一次生成立即使用源码默认值。

## 兼容现有配置

现有 `save` 行为会把两个有效提示词都写入配置文件。重置时按键删除目标字段并保留其余字段，因此无需迁移旧配置；重置后的目标字段会回退到源码默认值。

## 错误处理

- 不支持的 `kind` 返回 404。
- 配置写入失败返回 500，原文件保持不变。
- 前端只有在服务端确认成功后才提示恢复成功。

## 测试范围

- 存储层：保存两类自定义值后重置其中一种，目标类型回退源码默认值，另一类型保持自定义值；重新创建存储实例后结果仍成立。
- HTTP：DELETE 返回默认提示词；非法类型返回 404；随后 GET 返回正确的有效值。
- 前端请求模块：发送正确的 DELETE 请求并返回服务端确认的默认提示词；错误响应可见。
- 静态界面：白底图和场景图均存在恢复按钮并绑定对应类型。
- 回归测试：保存提示词和生成时强制读取服务端当前提示词的既有行为保持不变。

## 非目标

- 不新增“同时恢复全部提示词”功能。
- 不改变源码默认提示词文本。
- 不修改模型、输出尺寸、画质或其他生成参数。
